设计段落 3：后端 API 边界与 AI 接口预留

修正版：JWT 鉴权，影像上传后自动触发 AI，医生可手动重新触发。

接口组织方式

统一后端，按资源分组，按角色控权

医生端和患者端继续共用一套 API。前端通过角色进入不同工作区，后端通过 JWT 中的身份信息做权限校验。

鉴权建议

JWT 方案

登录成功后签发 JWT。前端在后续请求里携带 token，后端解析后识别医生或患者角色，并限制可访问的数据范围。

适合后续扩展 App / 小程序 / 多端
1. Auth 认证接口
  • 患者注册
  • 医生/患者登录
  • 刷新 token / 获取当前用户信息
  • 退出登录
/api/auth/*
2. Patients 患者档案接口
  • 医生端：患者检索、创建、详情、编辑
  • 患者端：查看自己的基础资料
/api/patients/*
3. FollowUps 随访接口
  • 按患者查询随访列表
  • 查看单次随访详情
  • 按拍摄日期自动归档或补建随访
/api/followups/*
4. Images 影像接口
  • 上传图片并填写拍摄日期、体位
  • 上传后自动触发 AI 任务
  • 获取某次随访下的图片列表
/api/images/*
5. AI 结果接口
  • 查询该图片的 AI 结果
  • 医生可手动重新触发 AI
  • 支持异步任务状态轮询
/api/ai/*
6. Reports 人工报告接口
  • 医生保存随访综合报告
  • 患者查看自己的最终报告
  • 支持草稿和最终提交
/api/reports/*
AI 触发流程

自动跑为主，手动重跑为辅

1. 上传图片
生成 image_id
→
2. 自动建任务
创建 AI task
→
3. 后端调用模型
异步执行
→
4. 结果落库
AIResult.image_id
→
5. 医生可重跑
重新触发任务
医生端权限边界

医生可调用

全部患者查询、全部随访查看、手工建档、影像上传、AI 重跑、人工报告填写。

患者端权限边界

患者可调用

注册登录、查看自己的档案与随访、上传自己的影像、查看自己的最终报告，但不能修改医生报告。

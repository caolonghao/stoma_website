设计段落 2：核心数据模型与权限边界

目标是让“一次随访”成为中心对象，同时保证医生端和患者端看到的是同一份真实数据。

建模原则

以“随访记录”作为业务核心，而不是以图片为核心

图片是随访的素材，AI 结果是辅助信息，人工判读报告才是最终医疗结论。这样模型更符合真实工作流，也方便后续扩展随访问卷、备注、复查建议等字段。

统一身份体系

一个用户表 + 角色区分

建议所有登录账号都放在统一的用户体系里，通过角色区分医生和患者，避免未来维护两套认证逻辑。

role = doctor / patient / admin
1. User 用户表
  • id
  • role
  • account 或 phone
  • password_hash
  • name
  • status
2. Patient 患者档案表
  • id
  • user_id，可为空
  • 姓名、性别、出生日期、手机号
  • 造口日期、造口类型、病历号
  • 建档来源：医生建档 / 患者注册
3. FollowUp 随访记录表
  • id
  • patient_id
  • followup_date
  • status：待AI / 待医生判读 / 已完成
  • source：患者上传 / 医生补录
  • created_at
4. Image 影像表
  • id
  • followup_id
  • 拍摄日期
  • 体位：端坐正位 / 端坐侧位 / 平卧位
  • 文件 URL / 存储 key / 缩略图
  • 上传人、上传时间
5. AIResult AI 辅助结果表
  • id
  • followup_id 或 image_id
  • 大类结果：5 分类
  • 细分类结果
  • 置信度
  • 原始响应 JSON
6. DiagnosisReport 人工诊断报告表
  • id
  • followup_id
  • 是否有并发症
  • 并发症类型，可多选
  • 分级：Ia / Ib / IIa / IIb / III
  • 医生意见、判读人、判读时间

医生端权限

可见范围

  • 查看全部患者与全部随访
  • 新建患者档案
  • 查看和上传影像
  • 触发 AI 辅助诊断
  • 填写和修改人工最终报告
患者端权限

可见范围

  • 只能查看自己的患者档案
  • 只能查看自己的随访和诊断结果
  • 可以上传自己的影像
  • 不能修改医生最终报告

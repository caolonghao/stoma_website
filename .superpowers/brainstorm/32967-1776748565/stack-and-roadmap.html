设计段落 4：技术栈建议、目录结构与 MVP 实施顺序

把方案从“概念正确”推进到“可以立即开工”。

推荐结论

首期建议用 Next.js 全栈 + MySQL + Prisma + 对象存储

你们现在是空项目、单科室、双端 Web、AI 接口暂未正式接入，这很适合用一套 TypeScript 全栈工程快速搭 MVP。

为什么这套合适

前端页面、后端 API、鉴权中间件、上传逻辑可以放在同一个工程里，开发节奏快，后续也足够承载医生端和患者端的演进。

A. Next.js 全栈
推荐
  • 前端：Next.js + React + Tailwind
  • 后端：Route Handlers / Server Actions
  • 数据库：MySQL + Prisma
  • 鉴权：JWT
  • 上传：S3 兼容对象存储
B. React + NestJS
更工程化
  • 前后端边界更清晰
  • 更适合后期多人并行
  • 但一期搭建成本更高
C. Vue + Java/Spring
传统后台路线
  • 适合已有 Java 团队
  • 稳定，但首期开发速度未必最快
  • 如果你们团队更熟这个，也能做

工程原则
1. 页面按角色分区
2. API 按资源分组
3. 权限判断收敛到 lib/permissions
4. AI 调用统一收敛到 lib/ai
5. 文件上传与对象存储统一封装
6. 数据模型以 FollowUp 为中心
MVP 实施顺序
1. 基础骨架
项目初始化、路由、数据库、JWT、角色权限
2. 医生端先跑通
登录、患者列表、建档、随访详情
3. 患者端补齐
注册登录、我的随访、影像上传
4. AI 占位接通
上传自动触发、结果落库、医生重跑
5. 报告闭环
医生人工判读、患者查看结果

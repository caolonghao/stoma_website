# 肠造口平台认证入口与前端层级优化设计文档

**日期：** 2026-04-21

## 1. 目标与范围

本次优化聚焦当前前端中最影响使用体验的一层：认证入口、访问边界与排版层级。

目标如下：

1. 将首页改为系统唯一公开入口，直接展示登录界面
2. 在同一张认证卡片中支持患者与医生两类用户进入系统
3. 在患者入口内同时支持登录与注册
4. 未登录用户只能停留在首页认证界面，不能访问业务页面
5. 登录后按角色分别进入患者工作台和医生工作台
6. 重整全局字体层级与认证页视觉风格，使界面更符合医学软件的简洁与清晰要求

本轮明确纳入：

- 首页信息架构重构
- 统一认证入口交互
- 患者登录 / 注册整合
- 医生登录入口收口
- 页面级访问控制
- 认证相关页面的视觉和字号体系调整

本轮明确不做：

- 医生端和患者端全部业务页面的彻底视觉重设计
- API 认证模式从本地存储 Bearer Token 全量切换为纯 Cookie
- 后台权限模型扩展
- 新增复杂品牌宣传首页或营销内容

## 2. 现状问题

当前实现已经具备基本功能，但存在以下不一致：

### 2.1 首页与系统入口不一致

- `/` 当前是“医生端 / 患者端”两个入口卡片
- `/login` 与 `/register` 是独立页面
- 用户需要先理解“入口页”，再进入真正的认证页，路径不够直接

### 2.2 未登录访问边界不够明确

- 患者页和医生页可以被直接访问
- 页面内部会提示“需要先登录”，但未登录用户依然能进入业务路由
- 这与医疗软件对边界清晰、权限明确的预期不一致

### 2.3 认证路径割裂

- 患者注册与患者登录分散在两个页面
- 医生与患者虽然使用同一认证能力，但在前端上没有统一入口
- 用户需要在多个页面间跳转才能完成认证

### 2.4 字体与视觉节奏不协调

- 认证和首页使用了偏展示型的大字号标题
- 标题、卡片标题、正文、辅助说明的尺寸跨度过大
- 背景装饰与 serif 标题更接近展示页，不够像稳定、理性的医学软件

## 3. 设计原则

本次前端优化遵循以下原则：

1. 单一公开入口：未登录时用户只面对一个入口，不暴露业务结构
2. 角色先行：先确认“患者 / 医生”，再展示对应认证动作
3. 操作闭环：患者可在首页内完成登录与注册闭环
4. 医疗软件气质：风格简洁、信息稳定、减少装饰噪音
5. 排版统一：用明确的字号、字重、间距层级替代当前跳跃的视觉节奏
6. 渐进改造：先修正入口与访问边界，再逐步扩展到业务页内部

## 4. 信息架构与页面流转

### 4.1 公开入口

首页 `/` 变为系统唯一公开页面。

首页不再承担“医生入口卡片 / 患者入口卡片”的选择功能，而是直接显示统一认证卡片。用户进入系统后的第一步不是“选工作台”，而是“确认身份并登录”。

### 4.2 认证卡片结构

统一认证卡片采用两级切换：

1. 一级切换：`患者` / `医生`
2. 二级切换：仅在患者下显示 `登录` / `注册`

对应关系如下：

- 患者 + 登录：进入患者登录表单
- 患者 + 注册：进入患者注册表单
- 医生：进入医生登录表单

### 4.3 登录后的流转

- 患者登录成功后跳转到 `/patient/dashboard`
- 患者注册成功后跳转到 `/patient/dashboard`
- 医生登录成功后跳转到 `/doctor/patients`

### 4.4 已登录用户访问首页

首页应在服务端读取当前用户：

- 如果当前用户是患者，自动重定向到 `/patient/dashboard`
- 如果当前用户是医生，自动重定向到 `/doctor/patients`

这样可以避免用户每次返回首页时重新看到登录卡片。

### 4.5 未登录访问业务页

未登录时访问 `/patient/*` 或 `/doctor/*`，应直接重定向回 `/`。

同时增加角色校验：

- 患者访问医生页面时重定向回 `/`
- 医生访问患者页面时重定向回 `/`

### 4.6 旧认证路径处理

`/login` 与 `/register` 不再承担独立认证职责，应统一重定向至 `/`，避免重复入口长期共存。

## 5. 页面结构设计

### 5.1 首页总体布局

首页定位为“认证首页”，不是营销首页。

页面主体由三部分构成：

1. 顶部轻量品牌区
2. 居中的统一认证卡片
3. 底部或卡片内的低强调辅助说明

首页不再展示业务工作台预览、不展示双入口跳转卡片，也不展示未登录用户无法执行的业务模块。

### 5.2 顶部品牌区

顶部只保留必要信息：

- 产品名称，例如“肠造口随访管理平台”
- 一句简短副标题，强调这是医生与患者共用的安全入口

其作用是建立上下文，而不是吸引点击或制造强烈视觉冲击。

### 5.3 认证卡片内容

认证卡片从上到下建议包含：

1. 当前场景标题
2. 角色切换
3. 患者登录 / 注册切换（仅患者显示）
4. 表单字段区
5. 错误提示区
6. 主按钮与少量次级说明

布局要点：

- 卡片宽度控制在中等范围，避免过宽
- 切换不同模式时保持整体布局稳定，避免明显跳动
- 错误信息统一放在表单靠下区域，不破坏整体秩序

## 6. 表单设计

### 6.1 医生登录

字段如下：

- 账号
- 密码

附加信息：

- 可显示默认测试账号提示，但应降级为低强调说明
- 不需要注册入口

### 6.2 患者登录

字段如下：

- 手机号 / 账号
- 密码

附加信息：

- 可保留“记住账号”这类轻量辅助能力
- 不额外暴露无关功能

### 6.3 患者注册

字段如下：

- 姓名
- 手机号
- 密码

注册完成后直接进入患者工作台，不再要求用户回到其他页面继续登录。

## 7. 视觉与排版规范

### 7.1 风格方向

整体采用“现代医疗风”，核心特征是：

- 简洁
- 明亮
- 专业
- 稳定
- 有轻微层次感，但不过度装饰

不再使用过强的海报式背景、戏剧化大标题或明显偏展示页的 serif 视觉主导。

### 7.2 字体策略

首页和认证相关页面统一采用稳定的无衬线字体体系。

推荐优先级：

- 中文：`PingFang SC`、`Hiragino Sans GB`、`Microsoft YaHei`
- 英文与数字：`Avenir Next` 或系统无衬线回退

原则：

- 页面主标题不再使用超大展示字号
- 卡片标题、表单标签、正文和辅助文案之间保留清晰但克制的层级差

### 7.3 字号层级

推荐全局层级如下：

- 页面主标题：`28px - 32px`
- 卡片标题：`20px - 24px`
- 分组标题：`16px - 18px`
- 正文：`14px - 16px`
- 辅助说明：`12px - 14px`
- 表单标签：`14px`
- 按钮文字：`14px - 16px`

该层级应同时适用于首页认证区和后续业务页收口。

### 7.4 颜色与界面层次

推荐色彩方向：

- 页面背景：极浅蓝灰
- 主卡片：高对比白色
- 主文本：深灰蓝
- 辅助文本：中灰蓝
- 主按钮：稳健的医疗蓝青色
- 错误提示：低饱和告警红

视觉层次通过以下手段建立：

- 轻阴影
- 细边框
- 稳定的圆角
- 极轻的背景渐变或层次

不依赖高饱和色块和复杂纹理。

## 8. 组件与实现边界

### 8.1 认证入口组件化

建议将首页认证区拆分为统一组件，而不是继续维护两个独立页面：

- 统一认证容器组件
- 角色切换组件
- 模式切换组件
- 医生登录表单
- 患者登录表单
- 患者注册表单

这样可以保证：

- 页面结构统一
- 样式来源统一
- 状态切换逻辑集中
- 后续扩展更容易

### 8.2 路由保护策略

本轮优先采用页面级服务端保护：

- `/` 在服务端判断已登录用户并跳转
- `app/doctor/*` 在布局或页面层统一检查是否为医生
- `app/patient/*` 在布局或页面层统一检查是否为患者

该方案与当前 `getCurrentUser()` 能力兼容，复杂度低于全量引入中间件改造。

### 8.3 业务页改造边界

本轮不重做全部业务页面，但需要同步做两类基础收口：

1. 统一页面标题、卡片标题、正文与说明字号
2. 让患者页和医生页在新视觉体系下不显得突兀

因此，本轮是“入口优先 + 页面基线收口”，不是“全站 UI 重画”。

## 9. 状态与错误处理

认证页应处理以下状态：

- 表单提交中
- 登录失败
- 注册失败
- 角色切换
- 患者模式切换（登录 / 注册）

交互要求：

- 切换场景时清理无关错误提示
- 提交按钮在 pending 时禁用
- 错误提示文案简洁、统一、位置固定
- 成功后直接跳转，不增加复杂确认层

## 10. 测试要求

本轮至少补充以下验证：

### 10.1 页面访问控制

- 未登录访问 `/patient/dashboard` 会被重定向到 `/`
- 未登录访问 `/doctor/patients` 会被重定向到 `/`
- 患者访问医生页面会被重定向到 `/`
- 医生访问患者页面会被重定向到 `/`

### 10.2 首页认证交互

- 首页默认显示统一认证入口
- 角色切换能正确切换到患者 / 医生场景
- 患者模式下可以在登录 / 注册之间切换
- 患者注册成功后进入患者工作台
- 医生登录成功后进入医生工作台

### 10.3 视觉回归重点

- 首页在桌面和移动端都保持表单清晰可读
- 字号层级与间距不再出现明显失衡
- 卡片内容不会因切换模式发生明显布局抖动

## 11. 实施顺序

建议按以下顺序推进：

1. 重构首页为统一认证入口
2. 将现有登录 / 注册表单整合到首页卡片
3. 将 `/login` 与 `/register` 改为回到首页
4. 为患者与医生路由增加页面级保护
5. 统一全局字体与认证页面样式变量
6. 收口患者页与医生页的标题层级
7. 补测试与回归验证

## 12. 预期结果

完成后系统将具备以下体验：

- 用户打开系统后直接进入登录界面
- 患者与医生从同一入口进入，但流程清晰分离
- 患者能在同一张卡片里完成登录或注册
- 未登录用户不能停留在业务页面
- 登录后自动进入自己的工作区
- 整体视觉更接近医学软件，字体层级更稳、更清晰
